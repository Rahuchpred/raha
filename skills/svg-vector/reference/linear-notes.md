# linear.app benefit figures, as shipped

Pulled 2026-10-26 from linear.app (the "Purpose-built / Powered by agents /
Designed for speed" row, labelled Fig 0.1 to 0.3). Sources: the SSR HTML,
stylesheet `DXpOFAO4.css`, chunks `C2FNh4D_2.js` (figures) and
`CAq5f4-d2.js` (grid loader).

## What they are

Hand-built inline SVG, generated by React components. No canvas, no WebGL,
no Lottie, no 3D library. Path data is template strings with the y values
computed (a helper rounds to 3 decimals: `Math.round(1e3*e)/1e3`).

## Projection

2:1 pixel isometric. Every plan edge runs 2 across for 1 down: slab corners
go from (14.145, y) to (129.183, y-57.519), that is 115.04 by 57.52. Fig 0.3
plates step (-8.45, +4.225) between neighbours. Vertical is plain screen px.

## Drawing a solid (Fig 0.1 slab, functions Xr Yr Or Kr)

Four paths per solid, in this order:

| Path | Fill / stroke | What |
|---|---|---|
| `Xr` | fill `#08090A` | The whole silhouette. Occludes everything behind. |
| `Yr` | stroke `#D0D6E0` 0.5 | Left side, top-back edges, right side (open path). |
| `Or` | stroke `#D0D6E0` or `#3E3E44` 0.5 | Bottom-front contour. Bright only on the hovered or last slab. |
| `Kr` | stroke `#3E3E44` 0.5, round cap | The lip: top-front contour, inset ~5px, 2px down. |

Corners are rounded with small arcs (`a3.43`, front `a10.29`, back
`a6.86`), drawn as circular arcs, not true projected ellipses.

Fig 0.2 cubes and Fig 0.3 plates use the same recipe. Plates use `#62666D`
for the outline and `#2E2E32` for the lip.

## Depth fog

Each cube in Fig 0.2 has a copy of its silhouette underneath with a drop
shadow: offset 0, `stdDeviation 16`, colour `#08090A` at alpha 1. It reads
as fog: lines behind a solid fade out near its edge. Fig 0.1's lid uses
`dy 4, stdDeviation 6`, alpha 0.6.

## Hidden lines

Fig 0.1 draws three dotted verticals (`stroke-dasharray 1 3`, round cap,
`#3E3E44`) through the stack, masked so they only show in the gaps.

## Motion

### Fig 0.1, stack lift (CSS transition)

```css
.purposeLift   { transition: transform .7s cubic-bezier(.32,.72,0,1); transition-delay: var(--lift-delay, 0s) }
.purposeLifted { transform: translateY(calc(var(--purpose-lift) * -1)) }
.purposeEdge   { transition: stroke .7s cubic-bezier(.32,.72,0,1); transition-delay: var(--lift-delay, 0s) }
/* reduced motion: transition: none */
```

Five slabs, index 0 at the top. Hovering slab `s` (capped at 3) lifts every
slab with index <= s by `--purpose-lift` (31.667px, the lid gap). Delay is
`(s - e) * 0.05s`, so the hovered slab moves first and the ones above follow.
Hit areas are static invisible strokes `0.894 * slabHeight` wide on each
slab's lip path, so a moving slab never steals the hover.

### Fig 0.2, dot-matrix loaders (CSS keyframes)

A 5x5 grid of r=1 circles, 3.5 apart, in a flat 16x16 SVG. Each dot gets its
own keyframes, opacity 1 (lit) or .3 (unlit), played with
`steps(1, end) infinite`, 200ms per frame. Frames are written as string art
(`●` lit, `○` unlit). Variants shipped: scope, upDown, pong, blowOut, ufo,
down, zap, hourglass, stats, cat, agent, empty.

They sit on the cube tops as absolutely positioned HTML over the SVG, tilted
with `transform: rotateX(60deg) rotateY(3deg) scale(.85) rotate(43deg)`
inside a `perspective: 1000px` wrapper. That is an eyeballed match to the
2:1 face. `iso.js` instead maps the grid onto the face with an exact affine
matrix, so the dots become true ellipses.

### Fig 0.3, pointer wave (framer-motion)

Fifteen plates. Resting heights (px):
`20.529 34.049 54.331 81.373 128.697 81.373 54.331 34.049 20.529 13.768 10.387 8.698 7.852 7.853 7.853`.

Pointer x in viewBox units drives a target height per plate from its
distance `t` to the plate's anchor (`anchor.x - 59`):

```
t <= 0   -> 128
t <= 25  -> 128 - t/25 * 88
t <= 60  -> 40 - (t-25)/35 * 28
else     -> 12
pointer gone -> resting height
```

The target runs through `useSpring({ damping: 18, mass: 1 })` (framer's
default stiffness 100) and `useTransform` rewrites both path `d` strings
every frame. The plate keeps its base; only the top rises.
